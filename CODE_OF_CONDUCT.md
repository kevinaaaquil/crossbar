# Code of conduct

## The short version

Be civil, argue about the work rather than the person, and assume the other
party is acting in good faith until they clearly are not.

## What is expected

- **Technical disagreement is welcome and encouraged.** This project is about
  measurement, and measurement claims should be challenged. Challenge the claim.
- **Be specific.** "This is wrong because the interval is computed over rollouts
  rather than tasks" is useful. "This is wrong" is not.
- **Accept correction gracefully.** Being wrong in public is the ordinary cost
  of working in the open, and it is a cheap price for a correct result.
- **Respect people's time.** Read the docs before opening an issue; search for
  an existing one; include enough detail to reproduce.

## What is not acceptable

- Personal attacks, insults, or demeaning comments.
- Harassment of any kind, in the issue tracker or anywhere else the project is
  discussed.
- Discrimination or derogatory remarks based on who somebody is rather than what
  they wrote.
- Publishing other people's private information.
- Sustained disruption of discussion, or bad-faith argument for its own sake.

## Scope

This applies to issues, pull requests, discussions, commit messages, and any
other space where someone is representing this project.

## Enforcement

Report a problem by opening an issue if it can be discussed publicly, or by
contacting the maintainer directly if it cannot.

Reports are handled privately. Depending on severity the response ranges from a
private word, to an edit or deletion of the offending content, to a block from
the repository. The maintainer's decision is final; this is a small project, not
a court.

## A note on tone

Terse is fine. Blunt is fine. Contempt is not. The difference is usually whether
the sentence is about the code or about the person who wrote it.
